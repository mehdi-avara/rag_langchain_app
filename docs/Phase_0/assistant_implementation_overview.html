Financial AI Assistant — Implementation Overview

Phase 0 · PROMPT_financial_assistant.md · modular monolith (FastAPI · PostgreSQL · LangGraph · Celery)

✓ implemented & tested (39 assistant + 17 financial tests pass)

1Architecture layers

A single generic engine; each domain module plugs in one thin adapter. The assistant never writes — it only proposes drafts.

Transport
assistant/routes.py — /assistant endpoints; SSE chat stream + draft endpoints.
Generic core reused by every module
runner (orchestration + streaming + history) · graph (LangGraph) · router (LLM intent) · registry (RBAC-filtered intents) · service (Draft/AgentRun) · intake (VLM/text) · rbac · errors · rate_limit · tracing
Financial adapter one per module
financial_management/assistant_tools.py — wraps existing services; builds drafts with their commit_target.
Existing module
financial_management/services.py & routes — the real create/update endpoints the frontend commits to.

The router only ever sees intents the caller is permitted to use. A user lacking a permission never has that intent named back to them — restricted tasks simply don't exist in their prompt.

3Turn flow (LangGraph)

router→ read/ write → draft/ general/ clarify→ decide_next→ end

Reply streaming (SSE)

Events: status · references · partial_draft · draft · delta · error · done. Structured objects are sent whole; only the answer streams token-by-token.

Two stores, kept apart

Transcript = ChatMessage rows (visible history, served by /chat/{id}/history). Resumable run = AgentRun.state snapshot. The Draft lives in its own table.

4Draft-and-Confirm the assistant never writes

user describes data (+file)→ agent builds Draft + commit_target→ frontend renders & user edits→ frontend POSTs to module endpoint→ POST /drafts/{id}/committed (record-only)
Chat text never commits. Even "yes / confirm / do it" only produces a pending draft. The write happens only when the frontend POSTs the final payload to the module's own route — there is deliberately no /confirm endpoint.

5Incomplete write → partial object + missing nouns

When required fields are missing, no draft is persisted. The assistant returns the object completed so far and names what's missing as nouns, then asks one question.

{
  "intent": "clarify",
  "partial_draft": {
    "target_action": "create_receipt",
    "payload": { "description": "pump", "amount": "100", "currency": "IRT" },
    "missing": ["credit card", "receipt date", "counterparty"]
  },
  "clarify_question": "I still need: credit card, receipt date, counterparty."
}

6File intake — VLM vs text branch

Vision model (supports_vision = true)

Sends OpenAI image_url blocks (base64) for images. PDFs → heavy Celery pipeline.

Text model

Never sends image blocks; sends extracted text only, wrapped as clearly-delimited quoted data (instructions inside files are ignored — §12.19).

Known gap: the VLM detection & block-building are implemented and tested, but the blocks are not yet fed into the router/answer model call (text-only today). Wiring that in is a small follow-up.

7Endpoints

POST
/assistant/chat
Agentic, SSE-streamed. May return a draft / partial_draft. Never commits. assistant:chat
GET
/assistant/drafts/{id}
Fetch / resume a draft. assistant:draft
PATCH
/assistant/drafts/{id}
Edit fields on the assistant-side copy before committing.
POST
/assistant/drafts/{id}/committed
Record-only notification — writes no domain data, re-checks no domain permission.
POST
/assistant/drafts/{id}/cancel
Discard a pending draft.

8Cross-cutting

RBAC

Runs as exactly the caller; read handlers & build_draft re-check permission. New perms: assistant:chat/draft/files.

Errors

Catalogued ASSISTANT_* codes only (unclear / draft-not-found / not-pending / rate-limited…).

Rate limit

Per-user & per-company sliding window → ASSISTANT_RATE_LIMITED.

Tracing

Fire-and-forget Langfuse (no-op unless configured). One trace per run.
