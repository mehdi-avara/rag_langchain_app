💡 What Is Phase 2?
Phase 2 is the maintenance loop. Phases 0 and 1 gave you the financial and procurement foundation — money, suppliers, materials, warehouse stock. Phase 2 answers the operational question: what physical equipment do we have, what's wrong with it, and how do we fix and maintain it?

The loop: An operator spots a problem on a tag → raises a Defect Report → a supervisor creates a Work Order (corrective maintenance) → a technician executes the work, consuming stock from the warehouse (auto stock movement) → the WO closes → the defect auto-resolves. In parallel, a Preventive Maintenance engine auto-generates work orders on a time or meter schedule so problems are caught before they happen.

What's new in Phase 2 that wasn't there before:
🏭 Plant → System → Asset hierarchy 📋 Work Order lifecycle 📅 Auto PM scheduling (Celery Beat) ✅ Inspection checklists 🚨 Defect / Fault reporting 🔔 Notification engine 📊 Maintenance KPI Dashboard

The headline KPI: "Number of critical tags with an open fault" — always visible at the top of the maintenance dashboard. A critical tag (defined in tag metadata) that has an unresolved defect is the system's most important signal.

🔄 Corrective Maintenance Flow (Defect → WO → Close → Defect Resolved)

Operator Report Defect on Tag → DEF-2026-XXXX (Open) headline KPI ↑
Supervisor Acknowledge defect → Raise WO from defect → Approve WO → Assign to technician
Technician Start WO (In Progress) → Record labor + materials → Stock OUT event → → Warehouse stock ↓
Technician Fill failure code + checklist → Mark Completed
Supervisor Close WO → Celery event → → Defect auto-resolved headline KPI ↓

📅 Preventive Maintenance Auto-Generation Flow

Planner Create MP → Tasks → Triggers → Set frequency (30 days / 500 hours) → PMSchedule row (Pending)
Beat Daily: find due schedules → Celery event → → WO auto-generated (PM type) status → Generated
Supervisor Approve → technician executes → Close WO → Update last_done_date → Next due date recalculated

📦 Material Consumption → Stock (WO material → warehouse)

Technician Record actual_qty on WO material → Celery event: ISSUE stock → StockMovement ISSUE in warehouse → StockItem quantity ↓
If stock hits reorder point → Low-stock notification → Planner creates MR (Phase 1 flow)

🔔 Notification Event Routing

Domain event fires → Celery: Notification engine → Match rules (event → role) → Bell + email to user
🚨 Critical defect raised → Supervisor 📋 WO assigned → Technician 📅 PM due tomorrow → Planner ⏰ WO overdue → Supervisor 📦 Low stock → Warehouse

📊 How the Headline KPI Works

tag has criticality A/B/C (tag metadata) + open DefectReport on that tag → counted in headline KPI
Resolved by: closing the WO (event) or manually resolving the defect → KPI count drops
