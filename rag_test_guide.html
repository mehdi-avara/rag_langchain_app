Ideal Document Types & Page Counts

The chunker uses MinerU (PDF parser) + token-based splitting (800 tok / 150 overlap). Documents that work best have dense, structured text — not scanned images.

🔧
Equipment Manuals
Maintenance procedures, specifications, troubleshooting trees. Rich technical vocabulary = strong semantic recall.
10 – 80 pages
📋
Inspection / SOP Reports
Structured sections, numbered steps. Both keyword and vector search perform well on these.
5 – 30 pages
⚙️
P&ID / Technical Specs
Valve specs, pump curves, instrument lists. Dense term tables are ideal for exact keyword matching.
3 – 20 pages
📜
Safety & HSE Procedures
Numbered regulations, permits, HAZOP findings. Q&A retrieval shines on "what is the procedure for X".
10 – 50 pages
📊
Financial / Procurement Docs
Purchase orders, invoices. The system has a dedicated financial module with receipt embeddings.
1 – 10 pages
📄
Simple Test (quick start)
Any text-rich PDF you have locally. Use a Wikipedia article exported as PDF for a no-effort demo.
2 – 5 pages

Sweet-spot parameters for this system

Pages: 5 – 50 (ideal)
Format: text-based PDF (not scanned)
Language: any (Jina is multilingual)
Chunk size: 800 tokens · 150 overlap
Max chunks: ~250 per 50-page doc

Avoid: scanned-image PDFs (MinerU won't extract text), purely graphical content, or files larger than ~200 pages without splitting first.

Interactive Test Harness

CORS note: All fetch calls go from your browser directly to the API. Make sure the backend has http://localhost:PORT (this file's origin) in cors_allow_origins in settings.py, or open this file via the same origin as the API, or use the Swagger UI at /docs for token-gated calls.
Step 1 POST /auth/token — Login & get JWT ▶

Sends application/x-www-form-urlencoded with username and password. The returned access_token is automatically stored.

Step 2 GET /documents — List your documents ▶

Returns all documents accessible to the current user. Note the id and status fields — only done docs have chunks ready for search.

Step 3 POST /documents/search — Keyword / Semantic / Hybrid ▶

Choose a search mode. keyword matches text via PostgreSQL full-text. semantic embeds the query and finds cosine-nearest chunks. hybrid does both.

Step 4 POST /documents/ask — RAG Q&A (single-shot) ▶

Retrieves the top-6 chunks semantically relevant to the question, builds a grounded prompt, and returns an LLM answer with [chunk:N] citations.

Step 5 POST /chat — Stateful agent chat (multi-turn) ▶

Like /ask but maintains conversation history and supports multi-source retrieval (docs + comments + financial receipts). Leave Chat ID blank for a new conversation.

Extra GET /documents/{doc_id}/chunks — Browse parsed chunks ▶

Inspect exactly what the system extracted and stored for a specific page range. Useful for verifying ingestion quality.

Testing Checklist & Tips

  1. Start Docker Compose: docker compose up. Backend on :8000, Celery worker for PDF processing.
  2. Login (Step 1). Default credentials are in your .env (default_username / default_password).
  3. Upload a text-based PDF via Swagger /docs or use /documents/import-processed-zip with a pre-processed zip for instant ingestion.
  4. List documents (Step 2) — wait until "status": "done" before searching.
  5. Run a semantic search (Step 3) with a conceptual question first to confirm embeddings exist.
  6. Run Ask (Step 4) and check the citations array — if empty, no relevant chunks were found.
  7. Use Browse Chunks (Extra) to verify what text was extracted from each page.
  8. If chunks exist but Ask returns no citations: check the LLM is reachable (llm_model setting) and the Jina API key is valid.

Quick curl reference

# 1. Login
curl -s -X POST http://localhost:8000/auth/token \
  -d "username=admin&password=yourpass" | jq .access_token

# 2. Search
curl -s -X POST http://localhost:8000/documents/search \
  -H "Authorization: Bearer TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"query":"pump seal replacement","mode":"semantic","limit":5}' | jq .

# 3. Ask
curl -s -X POST http://localhost:8000/documents/ask \
  -H "Authorization: Bearer TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"question":"What causes pump cavitation?","scope":"both"}' | jq .answer
